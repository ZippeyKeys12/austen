# `austen-harness`: Target runtime

The shared runtime behind the test harnesses generated by AustenTest (`austen test`).
It turns inputs into C arguments and checks the target's behavior against its specification.

The harness independently checks each input's precondition before writing memory or calling C.
Only a passing precondition reaches the selected target function.
Its postcondition is checked after the call returns.
Crashes and failed postconditions become findings.
A false precondition rejects the candidate.
Unsupported checks are reported as inconclusive.

## Using the runtime

To use the runtime with Austen, install the [austen CLI](https://crates.io/crates/austen), which generates the target-specific harness and links it to this runtime.
Set up the [native dependencies](https://github.com/ZippeyKeys12/austen/blob/master/README.md#building-from-source), then install the CLI:

```sh
cargo install austen --locked --features bennet,darcy
```

Given an exported specification `spec.json` and its corresponding C target `target.c`, run:

```sh
austen test spec.json target.c \
  --duration=2 --seed=7 --work=/tmp/austen-target
```

Building the CLI also builds and installs the shared runtime, so each new target needs only a small generated harness.
This crate's own executable has no C target linked and is used for runtime development and testing.

Use `austen test --check-heap-ownership` to enable allocation bounds, lifetime, and leak checks for supported targets.
This option also supports targets that free generated owned arguments.
Those arguments can otherwise crash when freed.

## Library API

Add this crate with `cargo add austen-harness` only when building your own Rust tooling on the runtime.

See the [Austen overview](https://github.com/ZippeyKeys12/austen) for the complete project.
The [user guide](https://github.com/ZippeyKeys12/austen/blob/master/README.md#try-it) covers testing workflows, and the [build guide](https://github.com/ZippeyKeys12/austen/blob/master/README.md#building-from-source) describes runtime behavior and build requirements.
